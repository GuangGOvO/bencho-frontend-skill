# bencho.dev 网页分析

分析基线：2026-10-05（Asia/Shanghai）。来源：[首页](https://bencho.dev/)、[组件面板](https://bencho.dev/blocks/slide-confirm)、[许可](https://bencho.dev/licence)。

## 已验证的网页结构

Bencho 是交互组件探索库。完整客户端首页有 **48 个组件**；检索 `confirm` 显示 `2 of 48`，与公开 JS 中解析出的目录一致。搜索抓取当时只有 40 项，因此目录以浏览器和运行包为准。首页按 Hover、Press、Drag、Slide、Swipe、Type、Select 七类筛选；导航还包含 Sounds、Finds、Bench。

卡片让用户直接体验交互，附有演示、编辑、收藏入口。滑动确认面板可切换预览/代码，调节明暗、描边、速度、宽度、圆角，并生成分享链接。代码页签曾呈现空白；不能据此宣称完成了官方源码导出验证。首页存在自动演示，单次点击后的状态可能受演示影响。

## 实测视觉参数

下表来自本次约 1092px 宽浏览器视口的 DOM 计算样式，而非完整设计系统。

| 项目 | 当前实测 | 对实现的启发 |
| --- | --- | --- |
| 页面 | 白色底、宽留白、居中介绍区 | 让用户注意力落在可操作对象上 |
| 主标题 | 40px，行高 42.4px | 标题短、层级明确，窄屏需另行适配 |
| 正文字体链 | Inter、Maison Neue、Instrument Sans、系统字体 | 新项目用已有字体或系统字体；不打包 Maison Neue |
| 导航 | 13px，行高 19.5px，间距 24px | 全局导航与组件演示保持清楚边界 |
| 卡片 | 圆角 28px，背景 rgba(23,24,26,.06) | 中性色舞台承托对象，不以全页装饰制造效果 |
| 前景文字 | rgb(23,24,26)，即 #17181a | 低饱和外壳加清楚的文字对比 |
| 当前布局 | 两列卡片，大块演示区域 | 展示库适用；业务列表应按信息密度重新决定 |

圆角卡片、胶囊控件、单色图标与灰色控件构成统一外壳。组件内部再用受力、液态连接、数字滚动和局部高光体现动作。它的辨识度主要来自**反馈方式**，不能只靠灰底加大圆角复制。

## 工程观察与限制

公开页面入口加载带内容哈希的 JS/CSS。包中可观察到 React、`framer-motion`、`lucide-react`，部分组件依赖 `liquid-gooey`；这是当前实现观察，不是版本保证，也不是本 Skill 的必装清单。

组件目录在客户端包中，普通 HTML 文本不足以覆盖完整目录。更新脚本提取白名单 metadata，并保留 JS/CSS 摘要；不执行抓取到的 JavaScript，不将整个网站代码重新分发。

原站 viewport 禁用了部分浏览器缩放。本 Skill 不沿用这一设置，使用正常可缩放 viewport。展示录音、上传、生成和资产兑换外观不能证明业务服务可用；需要在目标项目独立接入和验证。

## 迁移到目标产品

1. 将“灰色展示舞台”与“组件内部行为”分开，业务页面优先保留现有布局。
2. 选有实际反馈价值的交互：提交、选择、确认、加载、导航通常优先。
3. 用低幅度形变表达力度与方向；成功信息依然用可读文字表达。
4. 图像、图标、文案替换为项目自己的内容，装饰不改变任务可达性。
